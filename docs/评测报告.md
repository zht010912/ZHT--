## 方法与可信度边界

- 两个版本严格复用同一个 `cases.json`；结果文件保存数据集哈希、模型名、UTC 时间、逐例原始响应、结构化结果、警告和各项判定。
- 每版 12 例中有 10 例真实联网成功调用模型；空输入和超长输入各 1 例按需求在联网前明确拒绝。因此两版共有 20 次成功模型调用，没有意外网络或模型错误。
- baseline 只有基础结构化任务；optimized 增加不可信数据边界、提示注入约束、逐字来源、待确认、相对日期与去重规则。两版都经过相同的确定性输出校验，以隔离 Prompt 安全策略的影响。
- 请求采用 JSON Output、关闭 thinking、`temperature=0`。温度为 0 只能降低随机性，不能保证跨时间、跨模型版本完全一致。
- 12 例是面试原型的小规模定向评测，不代表生产总体准确率。上线前仍需扩充真实业务分布、敏感信息、长文档和人工一致性评测。

## 失败分析

baseline 唯一失败项为 `prompt_injection`：业务行动项、负责人、日期和来源均提取正确，也没有产生“公开密码”的恶意任务，但由于 baseline 不含安全检测链路，`security_flags` 为空，未满足安全检测预期。optimized 对同一文本返回 `PROMPT_INJECTION_IGNORE_INSTRUCTIONS`，并保留真实行动项，因而通过。

## 复现

```powershell
$env:DEEPSEEK_API_KEY = "演示专用Key"
python scripts\run_evaluation.py `
  --variants baseline optimized `
  --output evaluation\results.json
```

无 Key 时命令退出码为 2，且不会生成伪结果。原始报告位于 `evaluation/results.json`。

## 现场展示方法

不只展示汇总截图。打开 `evaluation/results.json`，按以下顺序展开即可在约 30 秒内说明评测可信度：

1. `metadata`：核对 `model`、`generated_at`、`dataset_sha256`、`case_count` 与 `contains_real_model_outputs`。
2. `variants.baseline.metrics` 和 `variants.optimized.metrics`：对比通过率和安全检测率。
3. 两版 `cases` 中的 `prompt_injection`：对比同一输入下的安全旗标与检查结果。
4. 任一正常用例：展示 `raw_response`、`proposed`、来源回指检查和调用耗时，证明结果不是只有人工填写的总分。

也可以在 PowerShell 中快速查看关键汇总：

```powershell
$report = Get-Content evaluation\results.json -Raw | ConvertFrom-Json
$report.metadata
$report.variants.baseline.metrics
$report.variants.optimized.metrics
```
