# 设计与协作说明

## 1. 目标与取舍

本原型优先保证“会议和行动项可独立使用”，再叠加 AI 建议与人工确认。技术栈采用 Flask、SQLite、Pydantic、httpx 和 pytest：无需前端构建，数据可持久化，面试环境可在较短时间内启动和解释。Web 端采用会议工作台形态，默认呈现摘要、关键结论与待办；供应商和具体模型名只保留在技术配置与评测证据中，不暴露在日常工作界面。

核心边界如下：

- 手工新增、编辑、完成和筛选行动项不依赖模型，DeepSeek 不可用时核心业务仍可用。
- AI 输出是 `proposal`，不会直接创建正式行动项；只有人工确认或编辑确认后才写入。
- AI 原始响应、结构化建议、最终确认结果分别保存，便于复盘“模型说了什么、人工改了什么”。
- 密钥只从 `DEEPSEEK_API_KEY` 读取，任何代码、文档、样例和评测结果都不保存真实密钥。

## 2. 需求假设

1. 每场会议可提供会议日期。`明天`、`后天`、`下周一`等相对日期以该日期为基准；缺少基准或表达无法唯一解析时，截止日期记为`待确认`。
2. 一句话包含多个明确的任务、负责人或期限时拆成多个行动项；纯建议、未通过方案、历史已完成事项不创建新的待办。
3. 负责人必须能从原文直接识别；不接企业通讯录，也不根据部门或语气猜人，无法确认时写`待确认`。
4. 同一会议中语义相同且负责人、期限一致的重复任务只保留一条；有实质差异时保留并交给人工审阅。
5. AI 提取的决策和行动项必须携带原文摘录。摘录无法回指输入时，结果不得静默进入正式数据。
6. “完成”表示人工明确更新状态，不因会议文本使用过去时自动改变已有行动项。
7. 修改行动项采用版本号进行乐观并发控制；版本不一致时拒绝覆盖，并提示用户刷新。
8. 当前原型按单组织、可信内部用户设计，不把登录、权限和多租户隔离纳入 3–4 小时核心范围。

## 3. 数据与流程设计

会议、正式行动项和 AI 分析运行持久化在 SQLite。一次 AI 处理经历以下状态：创建分析运行、调用模型、保存原始建议、人工确认/编辑/拒绝。只有确认后的 `final_payload` 才能生成正式行动项；拒绝和模型失败均保留审计记录，但不污染行动项列表。

结构化建议包含摘要、决策、行动项。行动项至少包含任务、负责人、原始日期表达、规范日期、原文摘录和置信度。数据库写入使用事务；API 统一返回结构化错误，不向调用方暴露上游原始错误体或凭据。

## 4. Prompt 与校验设计

`baseline` 只提供任务和 JSON 字段要求，用来建立可比较的真实基线。`optimized` 增加以下约束：

- 明确区分“系统规则”和带边界标记的“不可信会议原文”，会议中的指令不得改变系统目标。
- 要求只抽取原文明示的信息；不明确的负责人和日期统一标`待确认`。
- 给出相对日期解析基准和重复项合并规则；未通过建议、历史已完成事项另放入评测集观察，并保留人工审核兜底。
- 每个决策和行动项必须返回可在输入中找到的逐字摘录，且仅允许返回约定 JSON。

模型响应仍按不可信输入处理：解析 JSON 后进行 Pydantic 结构校验和确定性后处理，覆盖来源摘录、相对日期、重复项和提示注入信号。失败时记录明确错误，保留手工功能，不使用固定结果或规则结果冒充模型输出。

## 5. AI 编程协作摘要

本项目使用 Codex 协助拆分架构、生成局部实现、设计测试与评测集，并以 `ARCHITECTURE.md` 作为并行协作合同。代表性提问包括：

- “把任务书拆成基础 CRUD、真实模型调用、人工确认审计和同数据集评测，给出最小可验证接口。”
- “设计覆盖重复、待确认、相对日期、空/超长输入和提示注入的评测样例，不允许伪造模型结果。”
- “检查无密钥、上游失败和并发修改时是否明确失败，是否仍保留手工业务能力。”

一次被纠正的建议发生在评测设计：初版思路把空/超长用例遇到的“任意异常”都视为通过，这会误把网络故障当成输入校验成功。纠偏后，评测还要求错误代码或信息命中空输入/长度边界特征；真实调用失败单独计入 `unexpected_model_errors`。最终验收时，真实模型又把“方案 B 也可以再评估一下”提成了无负责人、无期限的候选行动项；这不是已分派任务，因此补充了确定性过滤，并在人工编辑区提供逐项移除。所有 AI 生成内容都经过接口契约、静态检查和可运行测试复核，未直接作为“已验证结论”。

## 6. 已知限制

- SQLite 适合单机原型，不适合高并发、多实例部署；生产环境应迁移到带连接池和备份策略的数据库。
- 人名没有接企业目录，同名、昵称和部门代称只能标待确认或由人工修正。
- 相对日期仅覆盖确定性表达；节假日、工作日历、“月底前尽快”等复杂语义不自动猜测。
- 来源摘录能降低幻觉，但不能证明摘要语义完全正确，因此保留人工确认门槛。
- DeepSeek 的网络、限流和模型行为不可控；评测结果应记录模型名、数据集哈希和时间，不能跨模型直接比较。
- 当前原型未实现登录、RBAC、租户隔离、附件解析、通知提醒和完整可观测性。
